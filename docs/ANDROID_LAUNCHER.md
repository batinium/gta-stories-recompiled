# The Android launcher

The app's home-screen entry (`LauncherActivity`). It works like a handheld console's home menu: a row of categories
across the top and, under the selected one, a list of its items. The background is a slow wave of light over a dusk
sky. Everything is drawn by us on a Canvas in the colours of the in-game overlay, so the app and the game look alike.
The app is called **GTA Stories Recompiled** (the runtime APK's `app_name`; a side-by-side build with `VCS_APP_ID_SUFFIX=.test`
is "GTA Stories Recompiled (test)"; a personal build with one game inside keeps "LCS / VCS Recomp Android").
The colours follow the game chosen in the header's **game switch** (below): Liberty City Stories' (steel blue `#74AEDA`
and amber `#F9B035` on navy `#0F0F22`, a crimson glow at the horizon, the default) or Vice City Stories' dusk (teal
`#3FE0CF` and pink `#FF5AAE` on dark purple `#1A1430`), one table for every view (`Palette.java`). We use no logos, art, fonts or
sounds from the game or from any console. (This file is separate from `docs/LAUNCHER.md`, which is upstream's PC
launcher.)

## The game switch (2026-11-18)

One app runs both games. The header shows **Liberty City Stories | Vice City Stories** (short `LCS | VCS` when the
window is narrow; on a very narrow one the switch takes the title's place), as the desktop launcher's title bar does.
**Liberty City Stories is first and selected on a fresh install** (`DiscCheck.GAMES` order; `GameFiles.game`: the saved
choice, else the game whose library is imported - LCS first -, else LCS); an existing user's last choice is kept.
A tap on a side, **Y** on a gamepad, or *Play > Game* picks the game; the colours crossfade (`Palette.fadeTo`, 0.35 s)
and every row re-reads its state. Each game keeps its own:

| What | LCS (default) | VCS |
|---|---|---|
| Disc (prefs `vcs`) | the same keys with `.lcs` after them | `disc.uri`, `disc.name`, `disc.ok`, `disc.game` |
| Game library | `files/game/lcs/libvcs_game.so` | `files/game/vcs/libvcs_game.so` |
| Data (memory card, caches, `locked_settings.txt`) | `files/userdata-lcs` | `files/userdata` |
| adb test disc | `.../files/disc-lcs.iso` | `Android/data/<pkg>/files/disc.iso` |
| Saves list, palette | `BASLUS-21423GTA30001`, LCS's | VCS's folder, dusk |

Shared by both: `vcs.ini` (settings), the controls, the stats overlay and frame generation (one Lossless.dll). Picking a
disc or importing a library files it under its own game (the disc check / the library's stamp say which) and switches
to it. The switch is greyed while a game runs (Play returns to the running one); a personal build with one game inside
`libmain.so` has no switch. Mods are per game too (`files/userdata[-lcs]/mods`; LCS's loader takes weapon / replace / stream mods). `GameFiles.migrate` moves
the layout from before (one library at `files/game/libvcs_game.so`, an LCS disc in VCS's keys) once.

## Screens (categories)

- **Play**: *Play* (needs the chosen game's disc and game library; shows the preset, resolution and fps cap the game
  will start with), *Game* (the switch as a row), *Test graphics* (the smoke test).
- **Disc**: *Choose disc image…* (system picker, checked in place by `DiscCheck`), *Import game library…*
  (`GameFiles`), and *Delete the test copy*. That last item appears only when a disc was picked **and**
  `Android/data/<pkg>/files/disc.iso` exists. It asks in a dialog first, with "Keep it" focused.
- **Saves**: *Import a save…* (.max, .cbs, .psu, .psv or a .zip; US PS2 saves only, asks before replacing the card's
  save and backs it up to `files/userdata/backups/<date-time>/`), *Export as .psu…* and *Export as .zip…* (system
  save dialog). Greyed out while the game runs. Its state line lists the slots on the card, or the last result.
- **Settings**: *Custom GPU driver (Adreno only)* first (below), the game's settings (table below), *Compatibility mode* (below), the stats overlay switch and its *items…* dialog.
- **Controls**: *Controller* (Auto / a connected pad / Touch only, the list read again each time it opens:
  `MenuView.Item.choice(Supplier, ...)`; ANDROID.md "Controllers"), on-screen controls mode, opacity, size, button
  haptics, camera, the three touch gestures (*Double-tap fires*, *Two-finger aim*, *Weapon swipe*, all on; ANDROID.md "Controls extras"), *L3 / R3 buttons* (Hidden / R3 in vehicles / L3 and R3), gyro (shown only when the phone has a gyroscope), phone rumble, controller vibration and the layout
  toggles.
- **Frame generation**: on / off, multiplier, flow scale, *Find Lossless.dll in a folder…*, *Search the folder again*
  and *Choose the file…* (the old picker, kept as a fallback).
- **About**: version and build tag (also faint in the bottom-right corner), bring your own disc, licence, where your
  data is; the updater (`UpdateMenu.java`, ANDROID.md "Releases and updates"): *Check for updates*, *What's new* and
  *Update* (shown when a newer release is found), *Check at start* (off by default).

A choice item opens its options in the same column. The current option has a teal dot. Picking one writes it and
closes the list.

## Input

- **Touch**: tap an item to activate it, or tap a category glyph, or a side of the game switch. Drag the list to scroll it (it flings). Swipe
  sideways to change category. Tap the `‹ heading` of an option list, or press Back, to close it.
- **Gamepad / keyboard**: D-pad or left stick (Android turns stick and hat motion into D-pad keys) moves around. Left /
  right change category; in an option list, left closes it. **A** / Enter / Space confirms, **B** / Escape goes back
  (B does nothing at the top level), **L1 / R1** (also Page Up / Down, Tab) change category, **Start** plays, **Y**
  switches the game. The
  hint line at the bottom shows gamepad buttons after a key press and touch hints after a touch.
- **Row explanations (2026-11-21)**: titles stay within about 24 characters and the grey line under them within about 40
  (it is ellipsized when longer, except on the selected row, which wraps to a second line). The full text lives in one
  place, `MenuView.Item.help(...)`: **long-press a row** (touch), **X** (or the Info key) on a pad, or tap the small
  **i** on the selected row, and `Host.showHelp` opens a dialog with the row's full value line and its help text.
  When you shorten a row, move the detail into its `help`, not into the value.
- System Back closes an option list. At the top level it leaves the app.

## Layout

`MenuView.layout()` works everything out from the view's size and the window insets (system bars, display cutout). No
dp value is fixed. The text unit `T` is `0.038 * sqrt(usable area)`, kept between 17 and 30 dp and at most 5.6 % of the
height. That gives about 60 px on the 1080x2420 cover screen and the 30 dp cap on the 2352x2172 inner screen. Wide
windows (more than 1.25:1) use a tighter bar and rows. Windows wider than 1.45:1 show the help text in a column on the
right; others show it under the list. The activity handles orientation and screen-size changes itself
(`configChanges`), so folding, unfolding or turning the phone only lays the menu out again.

## Settings it writes

**vcs.ini** (`files/vcs.ini`). The game reads it once at start: `src/main.cpp` `main()` calls
`settings::load(exeDirectory() / "vcs.ini")`, and `exeDirectory()` is `VCS_APP_DIR` (= `getFilesDir()`, set by
`VCSActivity`). The format and rewrite rules come from `src/settings/settings.cpp`. The launcher re-reads the file
before every write and changes only its own keys: in place, or appended when missing. Comments, unknown keys and line
order stay as they were. While the `:game` process is alive, the vcs.ini rows are greyed out, because the running game
would overwrite them on its next save.

## Compatibility mode

*Settings > Compatibility mode* (`CompatMode.java`, SharedPreferences `compat`/`on`; greyed while the game runs). On, the
launcher writes a managed block to `files/env.txt` between `# >>> compatibility mode ... >>>` and
`# <<< compatibility mode <<<`, leaving every other line as it is; off removes the block (and the file if it is then
empty). The game's native side reads the file at its start (`game_main.cpp loadEnvFile()`, logged per line), so the
launcher process and the `:game` process need no shared state. `tools/android.py env NAME=value` replaces the whole
file, block included: the launcher puts it back only when the toggle is changed.

| Line | Read in | Check | Effect |
|---|---|---|---|
| `PS2X_HW_SPECIALISE=0` | gs_hw.cpp `drawSampleMode` | first char `0` turns off | one general shader for every draw |
| `PS2X_RHI_FULL_BARRIERS=1` | rhi_vulkan.cpp | **presence** (any value, even `0`, enables) | whole-pipeline barriers |
| `PS2X_RHI_FULL_COPY=1` | rhi_vulkan.cpp `fullCopy` | non-empty and not `0` | whole-capacity dynamic vertex / index copies |
| `PS2X_CHAIN_ASYNC=0` | ps2_memory.cpp `asyncChainWanted` | first char `0` turns off (`verify` is a debug mode) | VIF1 chain walked on the render thread |
| `PS2X_RENDER_THREAD=0` | ps2_render_worker.cpp `configure` | non-empty: `0` off, else on | no render submission worker |
| `PS2X_GS_THREAD=0` | ps2_render_worker.cpp `configureGsStage` | non-empty: `0` off | no GS stage thread (it needs the worker anyway) |

`PS2X_VU1_COMPILED=0` and `PS2X_HLE=0` are not in the block: too slow to be a default.

**Auto safe mode**: when the renderer sees `VK_ERROR_DEVICE_LOST` (`rhi_vulkan.cpp reportLost()`, `[android]`) it creates
`files/gpu_lost.marker`. At the next launcher start / resume `CompatMode.consumeMarker()` deletes it; if the mode was
off it turns it on and a dialog says "The graphics driver crashed last time; compatibility mode is on. Turn it off in
settings if all is well."; if it was already on, a different dialog asks for the crash report (no silent loop, the
mode is not changed again). The crash report (`CrashReport.build`) states the mode and lists `files/env.txt`; the game
log has the `[android] env.txt:` lines. Not yet: offering to turn it off after N clean runs.

The item's value says "Off · Try this if the game crashes or does not start" when it is off.

## Untested phones and start-up errors

The launcher has no Vulkan context, so it learns the GPU from the game's own log. `DeviceNotice.scan()` (every launcher
resume) reads `files/logs/game.log`, then `game.prev.log`, parses the `[rhi] gpu: <name>, vendor ...` line (and
`driverVersion`) with `GpuLog` and keeps them in SharedPreferences `device` (`gpu`, `driver`, `api`), since the logs are
overwritten by the next run. Before the first run the key is the chip (`Build.SOC_MANUFACTURER` + `SOC_MODEL`).

- **Untested-phone notice**: `assets/tested_devices.txt` is the tested list: one rule per line, a case-insensitive
  substring of the GPU name (or of the chip name before a first run), `#` comments. Today: `Adreno (TM) 840` (Honor
  PNM-N49). A phone that matches nothing gets one dialog ("This phone has not been tested ...", buttons OK / Open
  settings), once per device key (GPU name + driver version, or the chip; `device`/`notified`): a driver update shows it
  again, the GPU becoming known after the chip's notice does not. It never blocks Play. About > Version also says
  "Untested phone". Add a GPU to the list once a log shows its exact name.
- **Start-up error**: when the last run's log has `[rhi] graphics cards ... (not usable: needs ...); using none` or
  `Failed to initialize runtime`, the next launcher start / resume shows "The game could not start" once per log
  (`failure_shown` = the log's modification time) with the cause in plain words (`GpuLog.explain`): "Your phone's
  graphics driver (Mali-G720 MC8) lacks: ...", "Vulkan 1.3 is required, this phone's graphics driver offers 1.1" (the
  renderer's message is `Vulkan 1.3 - this driver has X.Y`), a missing extension, or no Vulkan driver at all. For a
  missing feature it says to update the system / GPU driver and that Compatibility mode cannot fix it; with no known
  cause it suggests Compatibility mode. Button: Save report… (the same file picker as About > Game log). All three
  launcher notices (compat note, untested phone, this one) go through `LauncherActivity.showNotice`; one per resume.
- Check: `python3 tools/android_gpu_check.py` (the parsing on sample log lines, plain JVM).
- **Phone profiles (2026-11-22).** `tools/fixtures/device_logs/*.log` are synthetic logs in the real line formats for the
  phones we cannot own: Adreno 840 (tested), 750 / Mali-G715 (runs, untested notice), Mali-G720 (old build: no dual-source
  blend), Xclipse 940 / PowerVR / Adreno 619 tablet (Vulkan 1.1), Adreno 650 (missing features), no Vulkan, an unknown init
  failure, a device lost (Adreno 740), refused pipelines (the stock Adreno 840 bug) and a watchdog freeze. The first line
  of each says what the launcher must do (`# expect: tested= failure= explain= lost= refused= stalls= report=`);
  `tools/android_gpu_check.py` checks all of them (`DeviceProfilesCheck`), also that every start failure asks for the report
  and that a missing feature never promises Compatibility mode fixes it. To see the real dialogs on a phone:
  `python3 tools/android_device_sim.py run all` (debug `.test` app, phone unlocked; saves screenshots in
  `build/android/device-sim/`; it replaces the app's last game log and puts it back). Add a fixture for every new phone
  report: it keeps the next "it doesn't work" from being a new case. The report's Summary line now also has `gpu lost N`
  and `refused pipelines N` (ReportLog.deviceLost / refusedPipelines), the two silent failures seen so far.
- **What the launcher tells the player (dialogs, one per last run, never blocking Play).** In this order: a custom driver
  that failed (back to the system driver); a device lost (Compatibility mode turned on); a start that failed (the cause in
  words: missing feature / Vulkan too old / no driver, `GpuLog.explain`); **a run that started but went wrong
  (2026-11-22, `ReportLog.problem`): "The picture was black or incomplete" when the driver refused drawing steps (says it is
  the driver, not the game files; Compatibility mode does not fix it; update the system / a custom GPU driver on Adreno; send
  the report) and "The game froze" after a watchdog stall (turn on Compatibility mode, update, send the report)**; and the
  once-only untested-phone notice. Every one has "Save report..." and names the GPU. A native crash with no log line, a
  low-memory kill and a user swiping the game away are not told here (the report's Exit reasons has them): the log alone
  cannot tell them apart from a normal close.
- **Reading a report: `python3 tools/log_digest.py report.txt [--noise]`** (2026-11-22; also .rtf and raw `adb logcat -s vcs`):
  one screen with the phone, GPU, driver, what went wrong (start failure, device lost, refused pipelines grouped with their
  shader sizes, freezes, last exit, native crash), how it ran (fps, thermals) and, with `--noise`, which log prefixes take the
  room. Logging itself is automatic and small: a 3-minute LCS run is ~77 KB (half of it upstream's `sceCdSearchFile` disc
  lookups), the heartbeat is one line per 10 s, the `[caps]` block once, refused pipelines one line each (every pipeline
  only with `VCS_PIPE_LOG=1`), the device-lost draw ring only when it happens. A report is large (500 KB) because it also
  holds the system logcat tail.
- Not verified on a device. The maintainer's phone (Adreno 840) should show no notice and no "Untested phone".

## Diagnostics

About > Log and crash report… (save / share) is the only thing a player has to do. Its dialog lists, in plain words,
what the report holds and what it never holds (docs/ANDROID.md "Crash reports" > "Diagnostics"). The report's second
line is a summary for the maintainer: phone, GPU, driver, game, compat mode, custom driver, the game process's last exit
reason (Android 11+), thermal peak and the frame rate of the last run, and how many stalls the watchdog saw. A run that
did not end with `[android] game exit 0` also gets "where the last run stopped" (its last `[hb]` line and last 5 log
lines), and the same two go under the "The game could not start" notice. The share text is cut by section (header and
small sections whole, game.log keeps most of the rest), not only at its end. Check: `python3 tools/android_gpu_check.py`.
Not verified on a device.

## Custom GPU driver (Adreno only)

*Settings > Custom GPU driver (Adreno only)* (`GpuDriver.java`, SharedPreferences `gpu_driver`; the first row of
Settings, so the untested-phone notice's *Open settings* lands on it; greyed while the game runs). Enabled on a Qualcomm
chip (`Build.SOC_MANUFACTURER` QTI / Qualcomm) or an Adreno GPU in the last log; elsewhere greyed with "Not available:
Adreno (Qualcomm) GPUs only" and a help text saying Mali and other GPUs keep their system driver. The row opens a
dialog: a single choice of *System driver (default)* and every imported driver, *Import driver (.zip)…*, *Remove…*.

- **Import**: the first time a warning ("a custom GPU driver is native code that runs inside the game ... import only
  drivers from sources you trust"), then the system picker. `GpuDriver.install` streams the .zip: meta.json and `*.so`
  entries only (flat, plain names; other files skipped), at most 64 entries / 256 MB, every .so must be an ARM64 ELF
  shared object, meta.json must have `name` and `libraryName` (a plain `.so` name present in the zip), `minApi` <= the
  phone's API; `driverVersion`, `description`, `author`, `vendor`, `hardwareBufferFeature` are read for display / the
  record. Extracted to `files/gpu_drivers/<name>/` (staged in `.incoming-*`, then renamed; the same name is replaced)
  and selected. The launcher runs nothing from it.
- **Fallback**: VCSActivity writes `files/gpu_drivers/attempt.txt` when it starts with a driver. At the next resume
  (game not running) `GpuDriver.checkLastRun` reads `game.log`: no `[gpu-driver] confirmed` line, a
  `files/gpu_lost.marker` (taken here, so Compatibility mode is not switched on for the driver's failure) or a crash ->
  *System driver* is selected again and a notice says "The custom driver failed (...); the system driver is used
  again." with *Open settings*. One try per selection, never a loop.
- The untested-phone notice and the start-up error add, on Adreno phones, a line pointing to this row.
- The crash report has a `GPU driver:` line (system / the custom package, its version and library) and the imported list.

## Lossless.dll from a folder

*Find Lossless.dll in a folder…* opens the system folder picker (`ACTION_OPEN_DOCUMENT_TREE`) at Documents
(`primary:Documents`). The launcher keeps a persisted read permission on the chosen folder only. It does not use a
broad storage permission. It searches the folder breadth first (up to 8 levels deep and 20,000 entries) for
`Lossless.dll`, copies it to `files/lsfg/Lossless.dll` through `Lsfg.install` and turns frame generation on. If the copy
is ever missing, the launcher searches again by itself the next time it comes to the front.

## Extending it

- **A new item**: in `LauncherActivity.buildMenu()`, add `new MenuView.Item("Label")` to a category. Then chain:
  - `.value(supplier)`: the second line. Start it with `✓` for teal or `✗` for red.
  - `.help(...)`: the help text.
  - `.enabled(...)` / `.visible(...)`.
  - Either `.action(runnable)` or `.choice(names, currentIndex, pick)`.

  The suppliers run in `refresh()`, never while drawing, so they can read prefs and files. Call `refresh()` after any
  change.
- **Another of the game's settings**: add a `VcsIni.Setting` that copies the values and default exactly from the
  game's `settings::add` (cite the file:line), add it to `VcsIni.SETTINGS`, and add `iniItem(setting)` to a category.
  Values outside the game's choices are ignored by the game (`settings.cpp` `take()`).
- **A preference**: use `prefToggle` / `prefInt` / `prefPercent` with the store and key the game's side reads. Keep the
  same defaults as the reader.
- **A new category**: `menu.category(name, glyph)`. Add a `G_*` constant and a case in `MenuView.drawGlyph`, drawn as
  a simple line drawing of our own.
- **Colours**: only through `Palette` (`Palette.PINK` / `TEAL` / `GLASS` / `INK` / `BAD` / `EDIT`, read while drawing).
  Text is `INK` or an accent on `GLASS`; on an accent fill it is `GLASS`. Never white text on amber / pink, never
  crimson text. A new game: a `Palette.Set` and a case in `Palette.of`.
- **Something per game**: read `GameFiles.game(context)` when it is used (not once at start): the switch changes it.
